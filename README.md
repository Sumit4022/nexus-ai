# NEXUS AI

**A private multi-agent workspace for coding, document analysis, web research, and personal knowledge retrieval.**

NEXUS AI brings four focused assistants into one account-aware workspace. It combines streaming local inference through Ollama, Supabase authentication and storage, indexed document search, and cited web research.

## Highlights

- **Coding Agent** streams programming help, supports focused modes, reads text and image attachments, and keeps conversations available across sessions.
- **Downloadable responses** let the existing agents save answers as PDF, PowerPoint, text, or code files. The Coding Agent can create local SVG illustrations with SVG and PNG downloads.
- **PDF Analyst** extracts selectable PDF text, analyzes page images with a vision model, and answers with validated page citations.
- **Research Agent** searches the web with Tavily and streams a concise brief linked to the sources used.
- **Knowledge Agent** retrieves relevant passages from a user's own documents with PostgreSQL full-text search and cited answers.
- **Document library** extracts text from PDF, DOCX, TXT, Markdown, CSV, and XLSX uploads. Scanned PDF pages can be OCR processed.
- **Account history and settings** provide saved conversations, private per-user data, model readiness, and storage setup status.
- **Responsive workspace UI** includes a mobile navigation bar, accessible labels and states, reduced-motion support, and consistent loading/error feedback.

## Run locally

### Prerequisites

- Node.js 20.9 or newer
- npm
- A Supabase project with email authentication enabled
- Ollama reachable from the Next.js server
- A Tavily API key for the Research Agent

### Configure

1. Install the locked dependencies:

   ```bash
   npm ci
   ```

2. Copy `.env.example` to `.env.local`. Set the Supabase project URL and publishable key. Add `TAVILY_API_KEY` to enable web research. Keep `.env.local` private.

3. In the Supabase SQL Editor, apply every file in `supabase/migrations` in timestamp order. These migrations create account-scoped chat and document tables, row-level policies, atomic history saving, and indexed Knowledge search.

4. Start Ollama and pull the default text model:

   ```bash
   ollama pull qwen2.5-coder:7b
   ```

   The vision model enables scanned-PDF OCR, PDF page image analysis, and Coding Agent image attachments:

   ```bash
   ollama pull qwen2.5vl:3b
   ```

5. Start the app:

   ```bash
   npm run dev
   ```

Create an account at `/signup`, sign in, then use Settings to check Ollama, configured models, Tavily, and Supabase migrations.

## Configuration

| Variable | Purpose | Default |
| --- | --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase project URL | Required |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | Supabase browser-safe publishable key | Required |
| `OLLAMA_BASE_URL` | Ollama address reachable by the server | `http://localhost:11434` |
| `TAVILY_API_KEY` | Server-side live web search key | Research disabled when missing |
| `NEXUS_CODING_MODEL` | Coding Agent text model | `qwen2.5-coder:7b` |
| `NEXUS_PDF_MODEL` | PDF Analyst text model | `qwen2.5-coder:7b` |
| `NEXUS_RESEARCH_MODEL` | Research Agent text model | `qwen2.5-coder:7b` |
| `NEXUS_KNOWLEDGE_MODEL` | Knowledge Agent text model | `qwen2.5-coder:7b` |
| `NEXUS_VISION_MODEL` | Image and OCR model | `qwen2.5vl:3b` |

The older `OLLAMA_MODEL` and `OLLAMA_VISION_MODEL` names are also accepted as model fallbacks. Never put private service credentials in a `NEXT_PUBLIC_` variable.

## Data and security

- Dashboard routes and API operations require a valid Supabase session.
- Supabase Row Level Security policies scope workspaces, conversations, messages, and documents to the signed-in user.
- Database writes use the user's authenticated Supabase client; conversation replacement is performed by a transaction-backed RPC so a failed save does not erase the previous history.
- Tavily and Ollama requests run on the server. Private API keys are not returned to the browser.
- PDF, PowerPoint, text, and code exports are created locally in the browser. SVG illustrations are generated by the configured local Ollama Coding Agent; image generation is vector artwork and does not use a paid image service.
- Uploads are limited by size and type, extracted text is bounded, and supported PDF/OCR flows cap page counts and image payload sizes.
- Document and web source text is treated as untrusted context by the agent prompts. The app does not execute uploaded code or store original document bytes in the knowledge library.
- The project uses local Ollama by default. For a hosted deployment, configure a server-reachable Ollama endpoint and private environment variables; do not expose Ollama directly to the public internet without access controls.

## Operational limits

- Documents are limited to 10 MB and extracted text is capped at 300,000 characters per file.
- PDFs are limited to 500 pages. At most 20 scanned pages are OCR-processed during a single document upload.
- PDF questions can sample up to four page images. Original PDF bytes and rendered images are not saved to account history.
- Coding attachment extraction supports DOCX and PNG/JPG/WEBP images; attachment context is bounded and saved with the conversation for follow-up questions.
- Knowledge retrieval returns up to five matching documents and sends bounded excerpts to the configured model.
- Conversation history, Knowledge search, and document management require all Supabase migrations to be applied.

## Portfolio notes

The project demonstrates an end-to-end product slice: session-aware UI, authenticated server routes, streaming model responses, file ingestion, relational and full-text database work, citations, and deployment configuration. A live demo needs the owner to supply a configured Supabase project, Ollama service/models, and Tavily key; those credentials are intentionally not included in the repository.
